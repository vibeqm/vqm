1. **SECURITY** — `.claude/settings.json` lines 22–28  
   The deny list blocks the `Read` tool for `.env`, `~/.ssh`, `~/.aws`, and `~/.config/gcloud`, but the agent can read the same files through `Bash` (e.g. `cat .env`, `grep SECRET .env`, `sed -n '1p' .env`). The intended Level 2 control “denies the agent reading credential files and secret stores” is therefore bypassable.  
   Fix: add `Bash` deny patterns for those paths, such as `Bash(*.env*)`, `Bash(*~/.ssh*)`, `Bash(*~/.aws*)`, `Bash(*~/.config/gcloud*)`, or otherwise prevent Bash access to secret files.

2. **SECURITY / CORRECTNESS** — `tools/check_repo.py` lines 25–31  
   The version-consistency gate uses `data[m].get("version")` and only compares the resulting set.    Fix: require each of the three plugin manifests to have a non-empty `version`, and require a `vibeqm` entry in `.claude-plugin/marketplace.json` with a non-empty `version`; append a problem for each missing value before comparing versions.
